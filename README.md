# Visual Campus

**LOCUS Hackathon · Case 1 «Visual Campus»**

## Задача

Абитуриент хочет понять, как на самом деле выглядят кампус и студенческая жизнь вуза, но фотографии разбросаны по разным сайтам, часто без источника и с чужими местами. Нужно за ≤30 секунд по названию университета собрать **проверенный визуальный профиль**: фото по категориям, у каждого — источник, лицензия и уровень достоверности.

## Решение

1. **Распознавание** — пользователь вводит название (с опечатками, на любом языке). Бэкенд параллельно ищет в ROR и Wikidata, объединяет кандидатов и либо однозначно определяет вуз, либо предлагает выбрать.
2. **Сбор и проверка фото** *(следующий шаг)* — Wikimedia Commons, OpenStreetMap, Mapillary, Flickr, официальный сайт; для каждого фото считается шкала достоверности по доказательствам: геотег внутри контура кампуса, категория Commons, упоминания в описании, AI-распознавание сцены.
3. **Профиль** — фото по категориям, карта кампуса (2D / 3D / прогулка по панорамам), гид-маскот «Кампи», который отвечает только по найденным источникам.

## Запуск локально

### Backend

```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # ключи пока не нужны для /resolve
uvicorn app.main:app --reload --port 8000
```

Проверка:

```bash
curl localhost:8000/health
curl "localhost:8000/resolve?q=Korea%20University"
curl "localhost:8000/profile/Q39997?lang=ru"
```

Документация API: http://localhost:8000/docs

Тесты (без сети):

```bash
pip install -r requirements-dev.txt
pytest
```

### Frontend

```bash
cd frontend
npm install
cp .env.local.example .env.local   # NEXT_PUBLIC_API_URL=http://localhost:8000
npm run dev                        # http://localhost:3000
```

## API

### `GET /resolve?q=<название>`

Параллельно (asyncio + httpx, таймаут 5 с на источник) опрашивает:

- **ROR API v2** — сначала affiliation-матчер (устойчив к «грязным» названиям), затем обычный поиск для аббревиатур вроде `KAIST`;
- **Wikidata** — `wbsearchentities` → `wbgetentities` (координаты P625, сайт P856, категория Commons P373, ROR ID P6782). Если ничего не найдено, берётся исправление опечатки из поиска Wikipedia (`Koera Univrsity` → `korea university`), и ROR повторно опрашивается уже с исправленным запросом.

Кандидаты объединяются по ROR ID / Wikidata QID, иначе по совпадению названия и расстоянию ≤15 км. `match_score` = похожесть названия (с учётом алиасов и опечаток) + согласие двух источников + известность (число sitelinks в Wikidata).

| status | когда |
|---|---|
| `resolved` | лучший кандидат почти точно совпал по названию и заметно опережает остальных; запрос не является просто названием города |
| `ambiguous` | до 5 кандидатов на выбор |
| `not_found` | нет похожих кандидатов |

Если один источник упал или не ответил, ответ всё равно приходит, а в `sources_status` будет `timeout` или `error`. Если недоступны оба источника, возвращается `503`.

### `GET /profile/{wikidata_id}?lang=ru|en`

Проверенный визуальный профиль по `wikidata_id` из `/resolve` (например, `Q39997` — Korea University). Формат ответа соответствует контракту из `design/README.md`, плюс `stats` и координаты фото для карты.

1. **Wikidata** — названия на всех языках, координаты, категория Commons, статьи Wikipedia, центр города (штаб-квартира / «расположен в» → ближайший объект-город).
2. Параллельно, у каждого источника свой таймаут:
   - **OpenStreetMap** — контур кампуса: Nominatim по тегу `wikidata` (~1 с), при неудаче Overpass;
   - **Wikimedia Commons** — файлы из категории вуза и её подкатегорий (подкатегории о людях, логотипах и документах отбрасываются) плюс фото с геотегом в радиусе 1 км;
   - **Wikipedia** — краткое описание со ссылкой.
3. **Проверка каждого фото** (`backend/app/services/evidence.py`). Уверенность = 40 + сумма весов доказательств, ограничена 0–100:

| Доказательство | Вес |
|---|---|
| Геотег внутри контура кампуса | +28 |
| Геотег ≤500 м от точки вуза (если контура нет) | +20 |
| Геотег ≤1 км за границей кампуса | +6 |
| Геотег в 1–3 км / дальше 3 км | −10 / −30 |
| Нет геотега | −10 |
| В категории Commons вуза / в подкатегории | +22 / +16 |
| Название вуза в названии или описании файла (если файл уже в категории вуза) | +14 (+4) |
| Commons отметил снимок: Quality / Featured / Valued images | +8 |
| CLIP видит место (корпус, территория, читальный зал, аудитория…) | +12 |
| CLIP видит не место (портрет, мероприятие, машина, документ, гравюра, предмет) | −30, потолок «Не подтверждено» |
| Похоже на фото людей или мероприятия (вне кампуса) | −15 |
| Лицензия не указана | −12 |
| Снимок старше 15 лет | −10 |

   Уровни: **Проверено** ≥ 80, **Вероятно** ≥ 60, иначе **Не подтверждено** (в интерфейсе скрыто по умолчанию). Логотипы, гербы и схемы отбрасываются. Категория (кампус / общежития / аудитории / библиотеки / город) и теги (спорт, лаборатории, студенческая жизнь) определяются по ключевым словам на EN/RU/KO и по положению геотега. Дубликаты — одинаковый SHA-1 или кадрирование того же файла — прикрепляются к самой достоверной копии.
4. Результат кэшируется в памяти на 30 минут.

Проверено на живых данных:

| Вуз | Время | Фото | Проверено / вероятно / скрыто |
|---|---|---|---|
| Korea University (`Q39997`) | 6.0 с | 139 | 5 / 41 / 93 |
| KAIST (`Q39949`) | 10.8 с | 101 | 14 / 56 / 31 |
| Nazarbayev University (`Q2783344`) | 10.1 с | 71 | 3 / 47 / 21 |
| University of Cambridge (`Q35794`) | 13.5 с | 321 | 60 / 124 / 137 |

`404` — нет такого элемента Wikidata; `503` — Wikidata недоступна. Если OSM, Commons или Wikipedia не ответили, профиль всё равно собирается, а статус виден в `sources_status`.

## Готовые компоненты, AI и внешние API

- **ROR (Research Organization Registry)** — https://ror.org, API v2: поиск организаций, ROR ID, города, сайты.
- **Wikidata** — https://www.wikidata.org: сущности вузов, координаты, категории Commons, связка с ROR.
- **Wikipedia** — Search API (исправление опечаток) и REST API (краткое описание кампуса).
- **Wikimedia Commons API** — фотографии, авторы, лицензии, даты, геотеги, SHA-1.
- **OpenStreetMap** — Nominatim и Overpass API: контур кампуса (данные © OpenStreetMap contributors, ODbL).
- **Shapely** — проверка «геотег внутри контура кампуса».
- **OpenCLIP** (ViT-B-32, веса LAION-2B) — локальная zero-shot проверка, что на миниатюре место, а не человек или предмет.
- **Claude Design** — дизайн интерфейса, персонажа и состояний; исходники в `design/`.
- **Claude Code** — разработка: перенос дизайна в Next.js, бэкенд, проверки.
- **Шрифты** — Instrument Sans и JetBrains Mono (Google Fonts через `next/font`).

*Раздел будет дополняться по мере подключения карт (MapLibre GL JS), панорам (Mapillary, Kakao Roadview), Flickr и LLM.*

## Ограничения

- Бэкенд: работают `/resolve` и `/profile`. Фото пока только из Wikimedia Commons: Flickr, Mapillary и официальные сайты требуют ключей или парсинга и ещё не подключены. Что изображено на фото, проверяет локальная модель CLIP (ViT-B-32, CPU, без ключей): портреты, мероприятия, машины, документы, гравюры и предметы крупным планом не поднимаются выше «Не подтверждено». Модель видит только миниатюры, скачанные за 15 с, — у очень больших профилей часть фото остаётся без визуальной проверки. При первом запуске скачиваются веса (~600 МБ); `VISION_ENABLED=0` отключает проверку.
- Фронтенд: с реальным API работает **только поиск университета** (`/`). Остальные экраны — загрузка профиля, профиль, детальный просмотр фото, карта кампуса, гид и чат, гардероб, сравнение — пока на **демо-данных** (`frontend/lib/mock/`) и помечены плашкой **DEMO DATA**; следующий шаг — подключить их к `/profile`.
- Публичный Overpass бывает медленным и ограничивает частоту запросов; если он не ответил, профиль строится без контура кампуса (проверка по расстоянию до точки вуза).
- Веса доказательств и ключевые слова категорий подобраны вручную и проверены на небольшом наборе вузов. Старые архивные фото и снимки людей часто попадают в «Не подтверждено».
- Карта и 3D-вид — MapLibre GL JS на тайлах OpenFreeMap с данными `/campus` (контур, здания OSM по типам, пины фото). Высоты зданий в OSM часто не указаны — такие здания показаны условной высотой. Панорамы («Прогулка») ещё не подключены: режим честно сообщает, что их нет.
- В макете у поиска есть автоподсказки, но пока их нет: `/resolve` отвечает 2–4 с, для подсказок при вводе нужен отдельный быстрый эндпоинт.
- Классификация resolved/ambiguous подобрана эвристически и проверена на ограниченном наборе запросов.
