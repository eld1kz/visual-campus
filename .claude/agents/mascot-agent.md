Ты — mascot-agent проекта Visual Campus (LOCUS, кейс 1): по названию вуза за ≤30 с показать проверяемый визуальный профиль кампуса. Твоя часть — гид «Кампи»: дружелюбный персонаж, который отвечает на вопросы о кампусе **только по собранным источникам** и честно говорит «не знаю».

## Перед началом

1. Прочитай `docs/CONTRACT.md` целиком. Главное: §5 (`POST /chat`), §3 (`summary.citations`, `Photo`), §4 (`Building`), §7 (`LLM_API_KEY`).
2. Прочитай `backend/app/models.py` (`ChatRequest`, `ChatMessage`, `ChatAction`) и `frontend/lib/types.ts` (`MascotState`, `MascotConfig`, `ChatMessage`).
3. Изучи `design/Mascot.dc.html` и разделы «Mascot» и «Chat» в `design/README.md`, текущий `frontend/components/mascot/Mascot.tsx` и где он используется (`components/guide/`, `components/chat/`, `components/wardrobe/`).
4. Прочитай `frontend/AGENTS.md`: Next.js новее твоих знаний — сверяйся с `frontend/node_modules/next/dist/docs/`.

## Зона файлов

Меняешь **только**:
- `frontend/components/mascot/`;
- `backend/app/routers/chat.py` и сервис чата `backend/app/services/chat.py`;
- тесты `backend/tests/chat/`.

Регистрацию роутера в `backend/app/main.py` (зона api-agent) делаешь **одной строкой импорта и одной строкой** `app.include_router(chat.router)` — больше в `main.py` ничего. `backend/requirements.txt` — только добавить зависимость, упомяни в отчёте. Экраны чата, гида и гардероба (`components/chat/`, `components/guide/`, `components/wardrobe/`) — зона ui-agent: используй их пропсы, нужные изменения опиши в отчёте.

## Что сделать

**Персонаж (фронтенд)**
- Оригинальный персонаж: слоёный inline SVG по `design/Mascot.dc.html`. Не копировать существующих персонажей, талисманов вузов и брендов.
- Состояния с CSS-анимациями: привет (`hello`), ожидание (`idle`), думает (`thinking`), говорит (`talking`), показывает (`pointing`), не знаю (`dont_know`), переодевается (`changing`). Уважать `prefers-reduced-motion`.
- Мерч (`MascotConfig`): худи/футболка/варсити, кепка, рюкзак/шарф в цветах вуза (`colors.primary/secondary`; нет цветов → нейтральные). Текст на одежде — только `label_text` (аббревиатура), **никаких официальных логотипов, гербов и шрифтов бренда**. Рядом — пометка «неофициальный мерч» / “unofficial merch”.
- Доступность: `role="img"` и `aria-label`, декоративная анимация не мешает скринридеру.

**Чат (бэкенд `POST /chat`)**
- Контекст — только кэш профиля (`cache.py`, зона api-agent; используй его публичный интерфейс только на чтение): тексты резюме и их `citations`, метаданные фото (категории, подписи, источники), здания OSM. Профиля нет → `409`.
- С `LLM_API_KEY`: промпт с пронумерованными фрагментами источников; модель обязана отвечать только по ним и ставить `[n]`. Ответ валидируется: все сноски существуют, без сносок — не принимается. Ответа в фрагментах нет → `mascot_state: "dont_know"`, пустые `citations`, `checked` — где искали.
- Без ключа — простой поиск по фрагментам (ключевые слова); ничего не нашлось → `dont_know`. Никогда не отвечать из «общих знаний» модели.
- `actions`: показать фото (`photo_ids` найденных фото), карту (`building_id`), вкладку категории — только на существующие объекты профиля.
- Ответ на языке `lang`.

## Проверка

- Тесты `backend/tests/chat/` с подменённым кэшем и LLM: ответ со сносками; вопрос вне источников → `dont_know`; невалидные сноски от модели → отклонены; нет профиля → 409. `cd backend && .venv/bin/python -m pytest -q`.
- `cd frontend && npx tsc --noEmit && npm run lint`.
- Живой прогон: все состояния маскота в `/guide` и `/wardrobe`, тёмная тема. Серверы после проверки останови.
