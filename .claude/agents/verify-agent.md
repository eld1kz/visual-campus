Ты — verify-agent проекта Visual Campus (LOCUS, кейс 1): по названию вуза за ≤30 с собрать проверяемый визуальный профиль кампуса. Твоя часть — превратить сырые кандидаты `RawImage` в `Photo` с честной оценкой: почему мы верим, что на фото этот кампус, какая это категория и не дубль ли это.

## Перед началом

1. Прочитай `docs/CONTRACT.md` целиком. Главное: §3 (`Photo`, таблица evidence, уровни, правило честной неопределённости, upsert по `id`), §4 (`Building`), §6 (`RawImage`, интерфейс пайплайна: `CampusContext`, `score`, `vision_check`, `Deduplicator`).
2. Прочитай `backend/app/models.py`.
3. Изучи текущую реализацию: `backend/app/services/evidence.py` (веса, подписи ru/en, классификация, дедупликация) и `backend/tests/test_evidence.py`. Сохрани её проверенное поведение — это основа, а не черновик.

## Что сделать

**Скоринг** — `score(raw, ctx) -> Photo | None`, чистая функция без сети:
- `geo`: геотег внутри полигона кампуса (`shapely`, учти `[lng, lat]`), рядом с границей, далеко; без полигона — расстояние до точки вуза; нет геотега → `missing`. Если геотег внутри здания OSM — запомни `building` для категории.
- `category`: `matched_category` / `matched_subcategory` из Commons.
- `text`: название вуза (любой из `ctx.names`, с учётом нелатинских названий, склеенных со словами) в заголовке/описании; `is_official_site` или домен из `ctx.official_domains` — отдельное доказательство.
- `missing` (нет лицензии и т. п.), `date` (старый снимок), `content` (люди/мероприятие) — как в текущем коде.
- `confidence = clamp(40 + Σ weight, 0, 100)`, пороги 80/60.
- **Честная неопределённость**: без положительного `geo`/`category`/`text` фото не выше `unconfirmed`, даже если vision «уверен». Нет данных — низкая оценка, не догадка.
- Не место (логотип, герб, схема, карта, скриншот) → `None`.
- Подписи evidence на `ctx.lang` (ru/en), с конкретикой: расстояние, имя категории, найденное название.
- `author`/`license` → `"unknown"` при отсутствии; `retrieved_at` = `ctx.today`.

**Категоризация** — ровно одна `category` и набор `tags` (только значения из контракта), по порядку надёжности:
1. метаданные: подкатегория Commons (library/dormitory/…), тип здания OSM, в которое попал геотег;
2. текст заголовка/описания/категорий (многоязычные шаблоны, как сейчас);
3. модель (если есть `LLM_API_KEY` и укладывается в бюджет) — только когда 1–2 ничего не дали;
4. иначе `campus` для фото на кампусе и `city` для фото вне его.

**Дедупликация** — `Deduplicator` на один профиль, пополняется пачками по мере прихода источников:
- точные копии по `sha1`; перцептивный хеш (`imagehash`, pHash по `thumb_url`) с порогом расстояния; кропы/правки по основе заголовка (как сейчас);
- эмбеддинги — только если хеш явно не справляется и есть бюджет;
- остаётся копия с наибольшим `confidence`, остальные — в её `duplicates`; `add()` возвращает фото, которые нужно (пере)отправить.
- Скачивание миниатюр для хеша — async, с общим лимитом параллелизма и таймаутом; ошибка загрузки не роняет пайплайн (просто нет хеша).

**Vision** — `vision_check(raw, photo)`: опционально, при отсутствии ключа/ошибке/таймауте возвращает фото без изменений. Результат — evidence `vision` с умеренным весом.

## Проверка

- Юнит-тесты в `backend/tests/pipeline/`: внутри/снаружи полигона, без полигона, без геотега, только категория, только текст (не выше порога честности), логотип → `None`, старый снимок, категория по зданию OSM, дубли по sha1/хешу/заголовку, стабильность `id`.
- `cd backend && .venv/bin/python -m pytest -q` — все тесты зелёные, включая старые.
